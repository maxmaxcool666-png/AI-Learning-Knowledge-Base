# AI-Learning-Knowledge-Base

這是一個長期維護的個人 AI 技術知識庫，將 AI 討論、技術學習、實際操作與問題排除的成果，整理成具有長期參考價值的 Markdown 筆記。

目前已建立五篇正式技術筆記：第一篇[Git 基礎操作與安全提交流程](04-Git-GitHub/git-basics-and-safe-commit.md)，以及第二篇[GitHub Pages 部署與驗收](04-Git-GitHub/github-pages-deployment-and-verification.md)，以及第三篇[Codex 協作開發與安全修改流程](01-AI-Tools/codex-collaborative-development-and-safe-editing.md)，以及第四篇[網站響應式設計（RWD）與無障礙設計（A11y）](03-Web-Development/responsive-web-design-and-accessibility.md)，以及第五篇[Joomla 網站建置與上線實作](03-Web-Development/joomla-website-development-and-deployment.md)（整理 Joomla／XAMPP、Helix、上線及排錯的歷史紀錄），五篇驗證狀態均為「部分驗證」。分類架構、知識管理文件與忽略規則已建立，公開知識庫不收錄原始 AI 對話，私人歷史來源可另行保存且受 Git 忽略規則保護。

## 公開範圍與本機私人資料

- 正式技術筆記與知識管理文件可納入公開 Repository；正式筆記可保留「待驗證」「部分驗證」「已驗證」等狀態，公開不代表全部內容已驗證。
- 正式筆記中經使用者確認的個人學習心得與 Git 排錯經歷可以公開，仍須保留來源與驗證限制。
- `90-Inbox/` 是本機內部整理區，盤點、草稿及未經審核的整理資料不納入公開 Repository；僅允許保留 `.gitkeep` 空白佔位檔。
- 完整私人 AI 對話、原始匯出、私人帳號資料、密碼、API 金鑰及其他秘密資料不得直接提交公開倉庫；`local-private/` 為私人原始資料的預留位置，不公開。
- 公開筆記以文字說明未公開的私人來源，保留來源代號、證據摘要與限制，不連結至公開版本不包含的 Inbox 文件。
- `.gitignore` 是未來提交前的防護措施，不能取代內容檢查，也不能自動移除已追蹤的私人資料；`.env.example` 的例外僅適用經檢查且不含真實憑證的範例。

本知識庫已使用 Git 進行版本管理，並已建立 GitHub 遠端 Repository；上述公開策略仍適用。

## 建立目的

- 將分散的學習成果轉化成容易查找、理解與重用的知識。
- 保留背景、操作步驟、驗證證據與適用條件，支援後續實作與問題排除。
- 持續查證與更新，降低過時資訊及未驗證 AI 回答造成的誤用。
- 累積專案開發與實習準備所需的個人學習資產。

## 多 AI 平台知識整合理念

來源包含 ChatGPT（目前帳號）、ChatGPT（舊帳號）、Google Gemini、OpenAI Codex，以及未來使用的其他 AI 工具。正式筆記按主題與分類組織，不按 AI 平台拆分；相同主題整合到同一篇筆記，並允許記錄多個來源。

AI 回答是整理與查證的起點，應與官方文件、個人實作結果及推論分別標示。不同來源出現矛盾時，記錄差異並查證。個人化記憶摘要不能取代完整對話紀錄，缺少來源或驗證的內容必須明確標示。

知識庫不以保存所有原始對話為目標，僅整理具有長期參考價值的成果。

## 筆記撰寫與驗證原則

1. 使用 `00-Knowledge-Management/note-template.md`，填寫日期、分類與來源。
2. 文件使用繁體中文；技術名稱、程式碼與指令保留原文。
3. 聚焦可重用的知識，避免直接貼上冗長對話或重複建立主題。
4. 區分 AI 建議、官方文件、實作觀察與個人推論，不虛構經驗或結果。
5. 驗證狀態使用「待驗證」「部分驗證」「已驗證」；部分驗證須列出已確認與未確認項目。
6. 記錄驗證環境、版本、日期、方法、預期結果與實際結果。「已驗證」僅適用於記載的範圍與條件。
7. 未填寫內容保留明確佔位文字；未執行的操作註明「未執行」。
8. 維護有效參考連結與總索引，不加入不存在的筆記連結。
9. 公開前檢查個資、密碼、API 金鑰及私人對話內容；`.gitignore` 不能取代內容檢查。

## 知識維護流程

1. **收集**：將經敏感資訊檢查的學習重點或草稿放入 `90-Inbox`，記錄來源與問題。
2. **整理**：查找既有主題，整合重複內容，使用範本整理背景、知識與步驟。
3. **驗證**：比對官方文件，依適用環境實作，記錄證據、限制與未確認事項，更新狀態。
4. **分類與索引**：將有參考價值的筆記放入對應分類；尚未完整驗證者保留狀態與待辦事項。只有實際存在的筆記才能加入總索引。
5. **持續更新**：工具、版本或理解改變時重新查證，更新最後更新日期及驗證結果。
6. **歸檔**：將過時或不再維護的筆記移至 `99-Archive`，記錄原因與替代筆記（如已存在），同步調整索引。

來源規則見 `00-Knowledge-Management/source-guidelines.md`；總索引見 `00-Knowledge-Management/knowledge-index.md`。
